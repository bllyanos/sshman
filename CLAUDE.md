# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

sshman is a Linux desktop app (Wails v3 beta, Go + WebKitGTK, React/TS, Tailwind v4, shadcn/ui) that manages `~/.ssh/config`: list/search/view/create/edit/delete hosts, copy the ssh command, and open external terminals.

## Commands

```sh
wails3 dev                      # run app with hot reload (Vite on :9245)
wails3 build                    # native binary -> bin/sshman
go test ./internal/... ./services/...           # backend tests (no cgo needed)
go test ./internal/sshconfig -run TestDelete    # single Go test
cd frontend && npm test                         # vitest
cd frontend && npx vitest run src/lib/hostFilter.test.ts   # single file
cd frontend && npx tsc --noEmit                 # typecheck
wails3 generate bindings -clean=true -ts -i     # regenerate frontend/bindings after changing service signatures
./install-local.sh                              # build and install to ~/.local/bin (BIN_DIR overrides)
make -f .copr/Makefile srpm outdir=/tmp/sshman-rpm   # build the SRPM from HEAD
```

- Toolchain via `mise.toml` (Go 1.27, Node 20). Native builds need `gtk4-devel webkitgtk6.0-devel` (Wails v3 beta.33 uses GTK4/WebKitGTK 6.0, not GTK3).
- `go test ./...` from the root also walks `build/ios`, `build/android`; scope to `./internal/... ./services/...`.
- `frontend/.npmrc` sets `legacy-peer-deps=true`: npm 10 crashes resolving Vite 8's optional peers without it.

## Architecture

Dependencies point inward: `main.go` → `services/` → `internal/*`. `internal/` packages know nothing about Wails.

- `internal/sshconfig` — the core. `Parse` splits the file into a preamble plus `block`s (one per `Host`/`Match` line). Each block keeps its raw lines; only blocks marked `dirty` by `Create`/`Update` are regenerated in `Render`, so untouched text (comments, `Include`, odd spacing, `=` syntax) round-trips byte-for-byte — tests assert this. Trailing blank/comment lines belong to the preceding block. Key rules:
  - Only `HostName/User/Port/IdentityFile` are modeled fields; every other directive is kept in `Options` in order. First occurrence wins, as in ssh.
  - Hosts with wildcards or multiple patterns (`Host *`, `Host a b`) are `ReadOnly`; `Match` blocks are not exposed at all.
  - Alias lookup is case-insensitive. `Create` inserts before the first `Host *` so new values aren't shadowed.
  - `Store.Save` writes `config.bak`, then an atomic temp-file rename preserving the file mode.
- `internal/terminal` — `Known` emulator table (argv shape per emulator, plus an optional per-emulator ssh client and env, e.g. kitty runs `env TERM=xterm-256color kitten ssh` since the window starts without a shell, so `.zshrc` exports never apply). `Resolve` picks: explicit name → `$SSHMAN_TERMINAL` → first installed. Processes are started with `Setsid` and `--` before the alias.
- `services/` — the Wails-bound API (`HostService`, `TerminalService`). `HostService` reloads the file on every call (no cache) and serializes edits with a mutex.
- `frontend/bindings/` — generated by Wails, do not edit. Wails generates in interface mode (`-i`): models are type-only and slices may be `null`.
- `frontend/src/lib/api.ts` — the only module that imports bindings; it normalizes `null` → `[]` and exports the `Host`/`Option` types the UI uses. Keep components off the bindings directly.
- `frontend/src/lib/` — pure, tested helpers. `validateHost.ts` mirrors Go's `Host.Validate`; keep them in sync.
- `frontend/src/components/ui/` — shadcn components restyled for the neo-brutalist theme; tokens and utilities (`brutal-press`, `brutal-box`, `shadow-brutal*`, palette `yellow/pink/cyan/blue/lilac/red/ink/paper`) live in `frontend/src/styles/theme.css`. Radius is 0 everywhere. shadcn components import `cn` from the `cn` package.

## Packaging

- Fedora rpm via COPR: `packaging/rpm/sshman.spec`, entry point `.copr/Makefile` (make_srpm; packs `git archive HEAD`, so uncommitted changes are not included). The COPR build needs internet access for npm and Go modules.
- The spec builds with plain `go build -tags production` (no `wails3` on the builder) and installs the binary, `build/appicon.svg` as the scalable icon, and `build/linux/desktop` with `Exec` rewritten via `desktop-file-install`. Keep `build/linux/desktop` passing `desktop-file-validate`.
- Release: bump `Version`, add a `%changelog` entry, commit, then tag `vX.Y.Z` and push tags.

## Conventions

- Conventional Commits, small focused commits; commit and push after each finished checkpoint.
- When testing writes, never touch the real `~/.ssh/config`: run with a temporary `HOME` holding a copy.
